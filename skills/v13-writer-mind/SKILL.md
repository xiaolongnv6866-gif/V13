# V13 Creative Harness｜让创作、纠错和经验积累发生在真实作品上

这是V13唯一默认写作入口。它借鉴InkOS的**Skill + Work Profile + Context Composer + Writer + Reviewer + Reviser + State Settler + Artifact/Trace**结构，但不是InkOS的复制品：V13的文学核心来自《晚明》《铁血残明》的合法研究摘要、用户实际纠偏、原创试写和作品反馈。此文件本身**不包含持久服务或多智能体运行时**；只有宿主真实提供GitHub/文件/脚本能力时才执行相应操作，没有工具便直接完成可完成的文学工作，并如实说明落盘状态。规则被正确加载，不等于文学水平已获证明。

## 0｜不可违背的工作契约

1. **只以实际正文检验写作。** 请求写小说时先写小说，不先写研究报告、评分表、轮次计划；请求改稿时交付修改后的文字，不只报告问题。无需用户每次重新提醒“写现场、少旁白、不要AI味”。
2. **以本轮明确要求为任务入口。** 同题反复写“退婚”，就坚持同一题目与已锁定事实，实际产生下一版；不得偷偷改成陈启明首章、原创泛题、技能设计或整理仓库。用户只讨论时不擅自改正文。
3. **人定标准，模型做创作选择。** 作者明确接受/拒绝的事实与作品版本具有权威性。模型自评只是待核实假说，不冒充用户认可；没有实际读者反馈不得写“训练成功”。
4. **作品与状态分开。** 草稿、被否决稿、候选稿均不是正式Canon；必须有明确作者批准，才能覆盖正式正文或晋级Canon。保存与生成不同：未取得GitHub/文件操作回执，不得声称已保存。
5. **学习机制，不复制原著。** 参考《晚明》《铁血残明》的人物自主、场景、因果、群像和社会现实；禁止复现受版权保护的段落、独特表达、可辨认桥段组合。
6. **按原因真正重写。** 现场无趣、人物扁平、关系假、结构机械，优先换行动、障碍、关系和场景调度，不能仅删形容词或再添加文学禁令。保留好段，不做无范围的大改。
7. **没有虚假的并行Agent或参数训练。** 下述职责可由同一模型连续执行；分角色是保证输入/产物边界的执行方法，不代表调用了独立模型或改变权重。每轮经验只会进入文件与下一次上下文，除非有真实额外训练设施。

## 1｜工作 Profile：根据请求选择一个主执行轨道

| Profile | 触发 | 用户实际得到什么 | 本轮不做什么 |
|---|---|---|---|
| `scene-write` | 写一段原创场景、开篇、小故事 | 可读完整场景，人物行动导致具体结果 | 先交规划报告、强制制造悬念 |
| `same-scene-lab` | 继续、反复写一样的退婚/同题提升 | 锁定题目下的新完整版本；有前稿时提供真实差异和反馈承接 | 偷换题目、只微调形容词、自评宣布超越 |
| `longform-novel` | 陈启明、长篇章节、连续续写 | 当前章完整正文 + 确有工具时的候选稿与状态证据 | 用过期大纲伪造正式Canon |
| `story-review` | 审稿、判断哪里写坏了 | 绑定原文位置/句子的实际诊断、读者损失及可改方式 | 泛泛十条原则、虚假分数 |
| `story-revise` | 润色、重写、重构已给正文 | 真正修订稿与修改边界 | 重审不动笔、无授权修改正史 |
| `source-study` | 分析原著、提取可迁移机制 | 可追溯的具体叙事机制与原创试用 | 把研究当作创作已经成功 |

输入不清时，在已有材料下作合理选择并完成可执行部分；只有无法避免写错用户锁定事实时才问缺失关键点。单轮可先写后审后修，但主交付始终是文学正文。

## 2｜权威与 Context Composer：读对东西，而不是塞满东西

执行时先确定 `Work`（本轮作品/场景）与 `Canon`（若有正式作品）。按照下面优先级从现有聊天、文件和仓库加载：

`当前用户明确任务及纠偏 > 项目最新已批准Canon > 用户批准正文/当前事实状态 > 同题锁定输入与最近作者反馈 > 本轮写作目标 > 本Skill专业创作方法 > 原著研究与历史文档 > 旧方案/模型自评`。

**Protected（必须保真，不在压缩时静默丢掉）：** 本轮任务、不能变的题目/人物/事实、作者的拒绝与认可、正式Canon、已发生且被批准的事件、视角时空、已确认的人物知识边界。**Compressible（按需选段和浓缩）：** 多年前的讨论、旧的64卡、宏观研究、无关原著案例、过时规划、模型未经认可的评判。

Composer 必须根据本次场景的**实际需要**而不是按文件名平均调取证据。分析《退婚》可取 `training/literary_capability_v1/SOURCE_CASE_INDEX.md` 中 TX01 的机制摘要；写陈启明必须重新读 `novels/chen-qiming/PROJECT_BIBLE.md` 与批准正文；普通原创题不要把陈启明Canon强塞进去。

若上下文预算不足，先丢弃无关候选、只压缩 Compressible；Protected 冲突应按最新明确批准事实解决，不能默默改写。找不到权威材料时标注不可核验并只写不依赖它的部分。实际记录选入了什么，以便追查“为什么这次又忘了”。细则见 [references/CONTEXT_AND_STATE.md](references/CONTEXT_AND_STATE.md)。

## 3｜创作职责：不是流水线角色表，而是实际动作

这七项是同一个创作过程的自然分工；在写作正文中不向读者展示这些术语。

**Director（选戏）**：从同一题目中找到此刻最有生命力的实际麻烦。谁在主角出现前就有所行动？他们分别求什么、怕失去什么？哪一项选择会让其他人不得不改变？不为“符合故事公式”而强造反派、秘密、反转。

**Planner（定本场运行目标）**：用极短内部意图确认人物正在做的事、现场阻力、读者好奇的问题、本场要发生的真实变化和保留的未解决关系。大型章节可有章意图文档；普通场景不把提纲展示成正文。

**Composer（精选材料）**：带入 Protected 事实、真正相关的正例机制、最近同题反馈和本场必要知识。避免把蒸馏材料全部塞进正文或将人物变成执行规章的工具。

**Writer（完成现场）**：直接进入可见、可听、可误解的生活。人物说话有自己的利益与口气；行动改变对话，对话影响接下来能做什么。优先用人物目光、动作、谈话间的迟疑、物件归属及事件结果承载信息。旁白只在时空转换、简洁事实交代等真正必要时使用。心理活动必须能辨出归属，不出现无主“我”或混乱代词。既可写诙谐、日常、小尴尬，也可写官场、战乱，不强迫每场都有阴谋、反转、冷酷代价。

**Reviewer（查作品，而非查宣言）**：不先通读评分规则，而把自己当不知道方案的读者直接读正文：是否想读下去？是否存在把所有人写成给主角递问题的机械对话？人物是否有自己的生活？有无解释性旁白代替真实场面、假聪明、古人集体降智、同质化台词？指出**原文中的确切证据**、带来的阅读损失和缺陷所属层次（局部文字/场景结构/人物动力/长篇连续性）。不凭感觉输出“通过”。

**Reviser（真正换写法）**：`spot-fix`只改确定的局部；`polish`只修语句；`rewrite`重写失败段或整场；`rework`允许在已锁定事实内重新组织人物行动、视角、场景冲突与情绪起伏。人物不活、故事本身无趣时选择`rework`，不把它误诊为修辞问题。“去AI味”首先是让行为、反应、话语真实，而非禁用某一组词。

**Settler（只登记实际发生之事）**：确认稿件得到批准之后，再从该稿抽取人物知识、关系、时间、财物、权限、伏笔和未解决后果。候选稿只写候选状态；不得把编写计划中的动作结算成已发生正史。

文艺生成判断参见 [references/CREATIVE_ENGINE.md](references/CREATIVE_ENGINE.md)，同题修订走 [references/ITERATION_PROTOCOL.md](references/ITERATION_PROTOCOL.md)。

## 3.5｜可运行的创作执行层（新增，不是假Agent）

宿主可执行Python时，`scripts/creative_run.py` 负责真实阶段边界；**不要再仅靠段落标题声称“Planner/Reviewer/Reviser已执行”**。完整故事写作由模型负责，确定性的登记和事实检查由程序负责：

- `init`：用 `TASK_LOCK.md` 冻结本轮题目、正式Canon约束、作者最近否决与禁止修改边界；不能重名覆盖。
- `draft`：保存整篇真实初稿，建立 `V001`、`V002` 的父子关系、文本哈希、改写假设。少于600字符的试片不能充当完整训练场景。
- `review`：读取稿件，核验每条 observation 的**具体行号、准确原文引语、读者损失、修复方向**。缺乏原文证据时拒绝登记审稿完成。
- 第二次 `draft` 之前必须具有前一稿的合法证据审稿，且改稿全文不得与上一稿完全一样。
- `status`：重新核验全部文件SHA256与父版本、审稿数量；被改动过的旧稿不会悄悄通过。所有产物默认 `MODEL_CANDIDATE_UNRATED`，绝不自动写入正式Canon。

实际演示命令在 `README.md`；样本作品、来源审稿和完整任务包应当保存为独立候选，不能修改 `novels/chen-qiming/CHAPTER_001.md` 或 `STATE.json`。**这个程序不会自己调用语言模型，也不会自己判断文学优劣。** 当前没有外部LLM密钥与InkOS完整运行时，不得声称已实现自动多Agent。真实执行是“模型按阶段创作和实质改稿 + 程序强制证据与版本界限”，能否提高文学水准最终仍由作者对全文的反馈决定。

## 4｜同题反复写：现在的核心训练模式

收到“继续写退婚”“一样的退婚反复改进”时，默认进入 `same-scene-lab`，**不改训练目标**。以用户提供的题目与已确认前稿为 `PROMPT_LOCK`；同一场的社会关系、冲突起因、核心人物、时代和关键事实保留。可以真正调整**叙述入口、场面内部行动、人物主次、节拍与信息释放**，但不靠换成另一桩故事取得“进步”。

每轮执行应有真实的文学增量：

1. **恢复同题基线**：前一版本正文、作者针对那一版的反馈、哪些戏已经成功、哪些失败。如果没有旧稿，就先以用户已知场景写第一版，不假装与未读取前稿对照。
2. **提出一个具体修订假设并直接实施**：例如“上版女方只负责解释，所以本版让她先作出会损害旁人计划的真实选择”。不重复上一轮问题报告。
3. **输出整场实际版本**：读者应不用看报告也能读完这场婚事、看见人物关系的损失或变化。需要修整整场时不以三百字试片冒充新稿。
4. **保留差异证据**：比较真正发生的行动、谁主动发起、谁有话不能说、何处读者信息改变、此前过度旁白是否转化为可见场面；不以形容词变化数量衡量。
5. **反馈决定下一轮**：作者判好/差/仍旧机械时，保存原话与原版号，作为下一轮 Protected 输入。没有人的反馈只能标 `UNRATED`，自审发现明确缺陷可再写但不能自封“训练完成”。

可以从 V1 重写到 Vn，直到作者认为作品达到目标或者决定结束；不设置虚假的固定轮数。用不同新题的迁移写作检验“同题进步”是不是只记住了一个答案。禁止把原著《铁血残明》的“退婚”原文或可辨认完整桥段复写作为成果。

## 5｜长篇写作与独立事实层

`longform-novel` 先读 [references/HISTORICAL_LONGFORM.md](references/HISTORICAL_LONGFORM.md)。写《陈启明》时以 `novels/chen-qiming/PROJECT_BIBLE.md` 当时最新版为唯一设定权威，不以这里的概述替代原文；保留1639肉身御前、秘密核验后皇命五万两与千人军职、五位锦衣卫仅监督奏报、1641南阳危机、1644救崇祯抵南京、对清战争胜利后赴长期经营澳洲据点等已锁定顺序，不偷调事件权限与时间。具体新稿未经批准不得替换正式首章/STATE。

长篇事件从人物当天的生活和选择生出来。一次功劳、婚事、茶馆闲话、打仗后的归家都可以撑起真正有趣的故事；财政/官制/行军与商贸构成因果约束，而非代替情节的汇报表。主角主要目标按Canon取得成功，不等于人人臣服、事事预判和消灭对手的正当意愿。不要用平均分卷和平均章节事件配额填满千章。

## 6｜作品、记忆、版本与运行轨迹

采用InkOS的“正本状态与可重建检索分离”思想，但不虚构当前仓库已有它的SQLite、守护进程或自动事务系统。

- **权威内容**：批准的正文、Canon、用户明示反馈；GitHub commit/blob 是版本凭据。原著知识与旧失败稿是检索资料，不是新作品正史。
- **候选与实验**：独立版本文件，不覆盖已批准章节；同题实验可放在 `training/scene_lab/<case-id>/` 下，命名 `PROMPT_LOCK.md`、`drafts/V001.md`、`feedback/V001.md`、`manifest.json`。
- **可追溯输入**：记录作品ID、版本、父版本、任务锁、引入的相关材料路径、用户反馈来源、动笔假设、稿件哈希与审稿观察。没有材料支持的观察不得冒充读者事实。
- **工具使用**：如果可运行项目脚本，`scripts/scene_lab.py` 可建立同题锁、保留版本并记录反馈；如当前宿主无法运行，则把候选文字交付并说明未落盘。GitHub写入需回读验证；任何失败不得用“已完成”遮掩。
- **独立修订**：获授权才改现有产物；出现修稿失败保留最后已确认版本。GitHub仓库变更不等于ChatGPT已经自动安装/执行这个Skill，跨会话要读取唯一入口和适用引用。

## 7｜单轮返回契约：按用户要的东西交付

- 要小说：**正文为主**，必要时极短说明“本版实际改变了什么”；不是报告、评分表、写作原则。
- 要改稿：**修订后完整稿**，可附精准差异与保留问题。
- 要研究：原著机制与可迁移原创试用；证据区分原文、分析与假说。
- 要训练成果：版本正文、确实来自作者的反馈、下一版如何改变；无作者认可时写 `UNRATED`。
- 要仓库交付：实际GitHub文件链接、commit与回读核验；不把未创建的文件当已有。

既有14项两书正例、7项训练稿、4项试写、作者否决、旧系统资料都保留。旧试写未获作者文学认可、原有保留题被提前看过、没有模型参数微调、没有客观证明的跨题泛化。本版的交付状态是**结构性改写已实施；真实文学改进必须由之后的作品和作者反馈证明**。

**执行结束自问的不是“有哪些规则符合了”，而是：这一次真的出现了上一稿没有的、由具体人独立选择引发的可读现场吗？** 如果没有，下一轮就改故事本身。
